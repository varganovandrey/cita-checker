# Cita Monitor v2 (Madrid, TOMA DE HUELLAS)

Монитор свободных слотов на `icp.administracionelectronica.gob.es`. **Только уведомляет, не бронирует** — бронь дожимаете руками за те самые пять секунд.

Отличие от старых чекеров проекта: подключается по CDP к **вашему настоящему Chrome**, а не запускает голый chromium с поддельным UA. Отпечаток браузера настоящий, IP домашний — именно на этом ловились SeleniumBase-версии.

## Про токен бота

Токен и `chat_id` лежат в `monitor/.env` (в `.gitignore`). Взяты из `values.json` — это тот же бот.

Учтите, что сам `values.json` числится в git как отслеживаемый, то есть токен попадал в историю коммитов. Если репозиторий когда-нибудь уедет наружу, токен надо будет сменить через @BotFather → `/revoke`. Убрать файл из индекса, оставив на диске:

```bash
git rm --cached values.json
```

## Установка

```bash
pip install playwright python-dotenv && playwright install chromium
```

`playwright install chromium` нужен для служебных частей библиотеки; сам мониторинг идёт через ваш Chrome.

## Настройка

```bash
cp monitor/config.example.json monitor/config.json
cp monitor/env.example monitor/.env
```

В `.env` — новый токен бота и `TELEGRAM_CHAT_ID`.
В `config.json` — свои данные:

| Поле | Что вписать |
|---|---|
| `applicant.doc_number` | ваш NIE |
| `applicant.full_name` | имя как в документе, ЗАГЛАВНЫМИ |
| `applicant.doc_type` | `nie` / `pasaporte` / `dni` |
| `applicant.country` | страна рождения, как в списке сайта (`RUSIA`) |
| `filter.min_date` | `"2026-09-15"` — дата начала новой резиденции; слоты раньше неё полиция не примет, и уведомлять о них незачем |
| `filter.max_date` | верхняя граница или `null` |
| `schedule.run_at` | время запусков обхода, **по Мадриду** (`["09:30", "14:00"]`) |
| `schedule.run_days` | дни недели для запусков |
| `offices_per_cycle` | сколько офисов из `extra_offices` за обход |

Окно не может пересекать полночь — разбейте на два.

## Запуск

```bash
python monitor/monitor.py --test-telegram
```

Проверка связи с Telegram, сайт не трогается.

```bash
python monitor/monitor.py --verify
```

**Обязательный первый запуск.** Медленный проход с видимым браузером; в лог пишутся все `<select>` с опциями и все кнопки на каждом экране, HTML+скриншоты падают в `debug/`. Селекторы сайта не проверены на живой версии — если что-то разъехалось, здесь это видно. `«no hay citas disponibles»` в конце — это **успех** (`no_slots`), а не ошибка.

```bash
python monitor/monitor.py --once
```

Один заход. Коды возврата: `0` слоты найдены, `1` слотов нет, `2` блокировка, `3` ошибка.

```bash
python monitor/monitor.py
```

Рабочий режим. Полный обход по расписанию из `schedule.run_at` — по умолчанию **09:30 и 14:00** по Мадриду, каждый день. Между запусками спит, просыпаясь раз в полчаса, чтобы Ctrl+C оставался отзывчивым.

Один обход — это «Cualquier oficina» плюс все офисы из `extra_offices`, по 38 секунд на каждый и 20–50 секунд паузы между ними. Для 22 офисов это около 27 минут.

Если `run_at` оставить пустым, включается прежняя модель: окна активности из `schedule.windows` с интервалом `active_interval_minutes` внутри окна и `idle_interval_minutes` вне его.

## Что происходит при находке

1. Локальный beep + окно Windows (первым делом — слот живёт секунды).
2. Telegram с датами и скриншотом.
3. Вкладка Chrome остаётся открытой на экране дат и выходит на передний план — бронируйте.

Повторные уведомления о том же наборе дат подавляются на `notify.repeat_cooldown_minutes`.

## Что выяснилось на живом сайте

Три вещи, из-за которых старые версии не работали. Все проверены прогонами и сравнением с ручным проходом.

**Офис выбирается ДО услуги, на той же странице.** У `#sede` висит `onchange="cargaTramites()"` — он перезагружает список trámites через `POST /selectSede`. Если выбрать услугу, не тронув офис, уходит несогласованная пара и фаервол отвечает `Request Rejected`. Селектор `#idSede` из monitor-lite на этом сайте не существует.

**Поиск опции идёт по точному совпадению.** В списке стран есть и `RUSIA`, и `BIELORRUSIA O BELARUS` — вторая содержит первую как подстроку и стоит выше. Поиск по вхождению молча выбирал Беларусь.

**Фаервол судит по поведению, а не по запросу.** Ручной и автоматический POST на `acValidarEntrada` совпадали полностью: 20 полей с одинаковыми значениями, те же заголовки, тот же `Referer`, те же куки — но ручной проходил, а автоматический отбивался. Разница только в телеметрии: F5 ASM смотрит на поток событий мыши и ритм клавиатуры. Курсор, телепортирующийся в центр поля, и ровный интервал между нажатиями — достаточный признак. Поэтому здесь курсор ходит по кривой Безье со случайными паузами (`human_move_to`), между шагами есть холостые движения и прокрутка (`human_wander`), а каждый символ печатается со своим интервалом. Всё через CDP, то есть события трастовые — в отличие от JS-инъекций старых stealth-версий, которые фаервол видит насквозь.

Отсюда же вывод про темп: **не ускоряйте `action_delay_ms` и `typing_delay_ms`**. Полный проход занимает 40–50 секунд, и это не запас на всякий случай, а рабочее условие.

## Офисы: не везде делают отпечатки

Список услуг зависит от участка — при выборе офиса срабатывает `cargaTramites()` и перезагружает `#tramiteGrupo[0]`.

**Из 45 участков провинции отпечатки делают 22.** Проверены все.

**Ни один районный комиссариат Мадрида их не делает** — ни Ciudad Lineal, ни Centro, ни Chamartín, ни Salamanca, ни Retiro, ни San Blas. У всех ровно по 2 услуги, обычно carta de invitación и certificados. Внутри города отпечатки берут только два места: `CNP AVDA POBLADOS` и `CNP SAN FELIPE TIE` — второй специализируется именно на TIE, что видно уже по названию.

Остальные 20 — пригороды: Coslada, Torrejón, Rivas, Alcalá de Henares, Arganda, Getafe (два офиса по одному адресу), Leganés, Móstoles, Alcorcón, Fuenlabrada, Parla, Valdemoro, Aranjuez, Alcobendas, Colmenar Viejo, Pozuelo, Majadahonda, Las Rozas, Collado Villalba.

Отсюда и совет из чата про пригороды: дело не только в том, что там слоты появляются чаще — в городских комиссариатах их не бывает вовсе.

```bash
python monitor/monitor.py --discover-offices
```

Обзор перебирает офисы на одной странице через AJAX. Результаты копятся в `debug/offices_survey.json`, поэтому прерванный запуск продолжается с места обрыва, а не начинает заново. Темп намеренно неровный, с паузой каждые пять офисов: сорок шесть быстрых переключений подряд один раз уже словили `Request Rejected`.

Офис, где услуги нет, монитор считает нормальным исходом (`not_offered`), а не ошибкой: пишет строку в лог и идёт к следующему.

## Диагностика: запись ручного прохода

```bash
python monitor/record.py
```

Прицепляется к тому же Brave и пишет всё, что браузер отправляет, пока вы кликаете руками. Если сессия уже начата — вкладку не трогает. Именно этим сравнением и был найден поведенческий фильтр. Логи и HTML падают в `debug/` и содержат ваши персональные данные — папка в `.gitignore`.

## Логика исходов

| Статус | Как определяется | Реакция |
|---|---|---|
| `slots` | распознаны даты `dd/mm/yyyy` на экране дат | уведомление, вкладка открыта |
| `no_slots` | маркеры «no hay citas disponibles» | молча, следующий цикл |
| `not_offered` | услуги нет в списке этого офиса | строка в лог, следующий офис |
| `blocked` | маркеры блокировки, HTTP ≥ 400, **или страница без form/select/input** (сигнатура soft-block) | пауза 90–180 мин, одно уведомление |
| `error` | неизвестный экран | дамп HTML+PNG в `debug/`, **уведомление в Telegram** (не чаще раза в 6 ч), backoff до 30 мин |

Ключевое отличие от старых версий: там любой неожиданный экран считался находкой (`else` = «слот есть»). Здесь каждый шаг проверяет, что следующий экран действительно появился, и неизвестное никогда не классифицируется как `slots`.

Но и молчать о незнакомом экране нельзя: он вполне может **и быть** слотами — даты в непривычном формате, календарь-виджет вместо текста, изменённая вёрстка. Поэтому `error` шлёт уведомление со скриншотом и просьбой заглянуть в браузер, с ограничением раз в `notify.unknown_cooldown_hours` (по умолчанию 6), чтобы поломка вёрстки не превратилась в поток сообщений.

Распознавание дат держится на регулярке `дд/мм/гггг` — единственное место, где смена формата на сайте прошла бы незамеченной. Именно её и страхует уведомление о незнакомом экране.

## Файлы

- `monitor.py` — CLI, расписание, main loop, state
- `flow.py` — CDP-подключение, человеческий ввод, проход формы, классификация
- `notify.py` — Telegram + локальный алерт
- `record.py` — запись ручного прохода для сравнения
- `launch_browser.bat` — ручной запуск Brave с портом отладки
- `state.json`, `logs/`, `debug/`, `chrome-profile/` — runtime, в `.gitignore`

## Практика (из чата)

- Привязки к району прописки на отпечатки нет — принимают в любом участке провинции. Монитор идёт сначала по «Cualquier oficina», затем по конкретным офисам из `extra_offices`, по 4 за цикл с ротацией; список упорядочен от ближайших.
- На экране дат `Buscar` жмётся несколько раз: пул отдаёт случайные три слота, повторный поиск часто даёт более раннюю дату. Настраивается `check.buscar_retries`.
- Одна сита на один NIE — дубль система не даст.
- Слишком ранняя сита в Мадриде — потерянный слот, поэтому `filter.min_date`.
